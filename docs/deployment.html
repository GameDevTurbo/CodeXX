CODEXX SERVER / FIRST RUN

从下载到第一次请求。

一份给手动操作准备的部署清单。以你的 Apple Silicon Mac 为主线：安装 Docker、启动 Server、接入账号，再验证实际生成。预编译包无需安装 Python。

先确认这三件事

  • 芯片：“ → 关于本机”显示 Apple M 系列，请选 macOS-arm64；Intel Mac 选 macOS-x64。
  • 本机安装：此前安装的 Docker 应用、旧 CodeXX 包已移入废纸篓，旧 CodeXX 容器和卷已清理。与 CodeXX 无关的 Docker 数据保留。
  • 旧账号有备份：桌面的 CodeXX-private-backup-20261023 保存了旧配置和账号授权。首次手动体验可从空配置开始；需要恢复旧授权时先核对备份，不直接覆盖新配置。

本页无需联网即可阅读和勾选；下载软件及拉取镜像需要联网。勾选只记录人工进度，不会安装软件、启动服务或自动检测电脑。

1

下载正确的 Server 包

  1. 打开上方 Release 页面，下载 CLIProxyAPI-Server-macOS-arm64.zip 和同名 .zip.sha256。
  2. 将两份文件放在同一文件夹。在终端切换到下载目录，核对校验值：
cd ~/Downloads
shasum -a 256 -c CLIProxyAPI-Server-macOS-arm64.zip.sha256

显示 OK 后解压 ZIP，将整个文件夹放到你有写入权限、方便找到的位置。保留 App 与 Server.command 的相对位置。

请下载 Release 附件中的 ZIP，GitHub 自动提供的 “Source code” 是源码，不能直接当成预编译 App 使用。
2

安装并启动 Docker Desktop

  1. 从 Docker 官方网站下载 Mac / Apple silicon 版本。
  2. 打开下载的磁盘映像，将 Docker 拖入“应用程序”，然后打开 Docker。
  3. 按界面阅读并处理协议、安装设置及系统授权。管理员密码只在 macOS 系统弹窗输入。
  4. 等待 Docker Desktop 显示引擎运行。需要时在终端检查：
docker version
docker compose version

第一条应包含 Server 部分；第二条应返回 Compose 版本。如果提示找不到命令，可以重开终端，或检查 Docker Desktop 的命令行工具设置。

“已经安装”与“引擎正在运行”是两件事。首次启动时保持 Mac 解锁，并检查是否有管理员、钥匙串或文件访问弹窗。
3

打开 Server 管理工具

  1. 在解压目录打开 CLIProxyAPI-Server.app，也可以双击 Server.command。
  2. 界面加载后，确认 Docker Desktop 一项显示 Running。
  3. 新部署的 Configuration 显示 Not configured、Service 显示 Not deployed 属于正常状态。

App 尚未进行 Apple 开发者签名和公证。如果 macOS 阻止打开，先核对下载来源和 SHA-256，再按系统或组织允许的软件批准流程操作。

4

完成 Setup 并部署容器

  1. 点击 Setup。
  2. 需要让容器通过本机代理访问上游时，填写实际代理的 HTTP 端口；不需要代理填 0。不要凭空猜测端口。
  3. 点击 Generate and Deploy，等待下载镜像、创建配置并启动容器。
  4. 确认 Configuration 显示 Ready，Service 显示 Running。

新配置默认使用端口 8317。未检测到 Tailscale 时仅绑定本机；若已登录 Tailscale，GUI 会优先绑定其地址。初始化会保留已有配置与密钥，修改表单后再次初始化不会覆盖旧配置。

首次拉取可能较慢。拉取等待上限为 10 分钟，其他 Compose 操作通常为 2 分钟。超时后先检查状态和系统弹窗，Docker 后台任务可能仍在进行。
5

打开管理页，接入自己的账号

  1. 点击 Server 中的 Management Panel，或打开 本机管理面板。
  2. 管理面板使用管理密码登录。发布版 Mac 的凭据位于以下数据目录中的 .credentials.json：
~/Library/Application Support/CodeXX/Server

在 Finder 按 ⌘ + ⇧ + G，粘贴上述路径。隐藏文件可用 ⌘ + ⇧ + . 显示；在本机查看文件里的 mgmt_password。api_keys 用于客户端请求。

  1. 在管理页按上游类型完成账号授权，或填写你自己的上游 API Key。
  2. 确认授权完成并出现可用模型。
GitHub 登录只用于代码与发布，不会自动授权 ChatGPT、Claude 等上游账号。管理密码和 API Key 用途不同。
6

检查连接，再发送一次测试请求

  1. 点击 Server 的“检查连接”。它会检查带密钥的模型接口和无密钥请求的拒绝情况。
  2. 确认模型列表有你准备使用的模型。列表为空时回到管理面板检查账号和路由。
  3. 打开 CodeXX Client 或兼容客户端，填写以下信息：
项目本机填写值
API 基础地址http://localhost:8317/v1
API Key当前数据目录 .credentials.json 的 api_keys 中任意有效密钥
模型从服务实际返回的模型列表选择

发送一句“请回复：连接成功”，确认收到真实模型回复。此操作可能消耗上游额度；检查模型列表本身不会验证实际生成。

其他设备连接时，可使用 Server 的 Export .cliproxy 导出连接文件。远端设备不能使用你的 localhost，应使用其可达的服务地址；需要时再配置 Tailscale。

卡在哪一步，就检查哪一层

Docker 一直 Not running / Checking

打开 Docker Desktop，确认引擎就绪；检查锁屏、管理员、协议与钥匙串弹窗。如果 Server 状态长期不刷新，确认使用的是新版包并重新打开管理工具。

镜像拉取慢、没有进度或出现 TLS 错误

检查网络，以及 Docker Desktop 自己的代理设置。Docker 下载镜像所用的代理与容器访问上游所用的代理是两套设置。检查钥匙串提示，等待当前任务结果后再决定是否重试。

容器卡在 created / Starting

检查 Docker 的目录共享与 macOS 文件访问授权，确认数据目录存在。查看 Live Logs 或数据目录下的 docker compose ps；先确认当前状态。

容器 Running，但管理页打不开

检查端口 8317 是否被占用、端口映射和容器网络，以及管理页资源的下载情况。管理页和业务 API 应分别检查。其他电脑访问时请使用可达的服务地址。

请求返回 401，或模型列表为空

401：确认客户端使用当前 API Key，管理面板使用管理密码。模型为空：检查上游授权、模型配置和路由；列表成功仍需另做实际生成测试。

需要导出诊断信息

在解压目录打开终端，执行只读诊断。它不会启动容器或发送生成请求；新部署未完成时返回未就绪是正常结果。

./CLIProxyAPI-Server.app/Contents/MacOS/CLIProxyAPI-Server \
  --doctor --probe --report doctor.json

分享报告前检查其中的本机路径和地址。不要分享凭据文件或 auths 目录。

部署之后

  • 关闭窗口：仅关闭管理界面，容器会继续运行；点击 Stop 才会停止服务。
  • 关机与休眠：退出 Docker、关机、休眠或网络切换都可能中断服务。恢复后依次检查 Docker、容器与 API。
  • 升级与备份：升级前备份数据目录中的 config.yaml、docker-compose.yml、.credentials.json 和 auths/。使用命名卷的旧部署还要单独备份卷。
  • 其他系统：Windows 下载 Windows-x64 包，运行 Server.bat；Linux 下载 Linux-x64 包，准备 Docker Engine 与 Compose 后运行原生程序。各系统的数据目录不同，见包内文档。

验收按四层进行：配置已生成 → 容器已运行 → API 鉴权通过 → 实际生成成功。每一层都确认后，再开始配置其他设备。
